## 2. 任务标签与实际规模

任务是蛋白序列到 GO 的多标签预测，分 MFO/BPO/CCO 三本体；评估沿用 CAFA 的时间延迟实验注释，不是 EC 单标签/多标签划分，也不是静态随机划分。NK（type1）表示该本体原先无实验知识，LK（type2）表示已有部分实验知识。未标注 GO 不自动等于经过实验否定的负功能。

| 数据层 | 实测规模 |
|---|---|
| t0 训练 | 66,841 条 Swiss-Prot 序列/蛋白；386,197 条蛋白–GO 注释；24,266 个不同 GO；F/P/C=67,600/203,696/114,901 条 |
| targets | 24 个 FASTA 文件（23 个 taxonomy ID 加 moonlight），130,827 个唯一蛋白 ID；126,138 个不同序列 MD5，故 4,689 个 ID 超出唯一序列数 |
| MFO t1 | 1,765 个 leaf-only 蛋白–GO 对，1,101 蛋白，631 GO；NK/LK=454/647 |
| BPO t1 | 3,608 对，2,145 蛋白，1,673 GO；NK/LK=849/1,296 |
| CCO t1 | 1,800 对，1,097 蛋白，327 GO；NK/LK=639/458 |
| 全部 t1 | 3,328 个唯一 benchmark 蛋白；NK=1,177、LK=2,151，二者全局不重叠；2,631 个不同 GO |

所有 3,328 个 benchmark ID 均在 target FASTA 中找到。旧执行文档的“28,679 targets、3,228/1,035、677 术语”不是此固定 CAFA3 包的实测规模，不得沿用。`T2089630000462` 在 BPO NK 清单中但不在 `leafonly_BPO.txt`，是上游文件自身的不一致；保留异常记录，不擅自补标签或删除后冒称原榜协议。

## 3. 清洗合同

1. 保留 CAFA3 ID、UniProt accession、taxonomy 与序列的映射；不得仅用行号连接训练、target 和真值。
2. t0 标签文件已是三列 `<accession, GO, namespace>`，没有逐注释 evidence code；它由组织者预过滤为实验注释，不能再声称本审计逐条核验了 EXP/IDA/IMP 等代码。
3. t1 只使用固定 commit 的 leaf-only ground truth；GO 祖先传播、信息内容和 Smin 必须使用同 commit 的 `go_cafa3.obo`。不得用当前 GO/GOA 回填 t0 或 t1。
4. 对相同序列的不同 ID 建立全局 `sequence_md5`/精确序列组；去重只用于训练拟合与同源审计，评价时仍按官方 ID 和清单计算，避免改变分母。
5. 序列长度、非标准氨基酸、空序列、ID 缺失和重复注释在构造模型输入时另行输出逐文件计数；当前审计没有静默过滤这些记录。
6. BPO 异常 ID 在“忠实 CAFA”轨保留并显式报告其无 leaf-only 真值；若另建修复轨，必须改名并同时报告原轨，不能替换官方清单。

## 4. 时间与同源划分设计（待执行，尚非已生成 split）

- **主轨：忠实 CAFA3 时间留出。** t0 为唯一训练/选参来源；固定 NK/LK t1 只在最终评价读取。t0 内再划 train/validation，validation 只用于早停、阈值、温度和模型选择；不得用 t1 选任何参数。
- **t0 内验证。** 若补得早于 2016-09 的可靠历史快照，可按更早时间再切 validation；否则按精确序列组和 MMseqs2/UniRef50 同源簇做组独占验证，并明确这只是 t0 内代理验证，不是第二次时间 OOD。
- **同源两轨。** 原始 CAFA 轨允许训练与测试存在同源，报告每个 t1 蛋白到 t0 train 的最大 identity/覆盖度分桶及 BLAST 基线；压力轨在不改变 t1 的前提下，按预注册阈值（90%/50%/30%）剔除与 t1 过近的训练序列。不得根据 t1 成绩移动阈值或重排 test。
- **训练白名单。** 数据加载器显式枚举 t0 train ID；validation、NK/LK t1、无 fold 的 `fold=-1` 不得经补集表达式进入 train。最终 test 只评价一次，逐本体、NK/LK、频率与同源桶分别报告。
- **指标。** 主指标为 CAFA Fmax/Smin 及 coverage；长尾宏指标作为补充，不以普通 AUROC 替代 CAFA 评价。BLAST/naïve 是同协议必要基线；文献榜单数字不冒充本项目实测。

## 5. 许可证与边界

- CAFA3 论文页面标明正文 CC BY 4.0，论文中数据在未有其他声明时适用 CC0；评估仓库的 `LICENSE` 是 GPL-3.0，约束其代码，不能简单据此给全部上游数据统一贴 GPL 标签。
- 两个官方压缩包未附单独的数据 LICENSE 文件。公开下载不等于任意再分发许可；再分发前仍需核对 CAFA、UniProt 和 Gene Ontology 的上游条款。本卡只记录内部研究落地，不作法律授权判断。
- CAFA5 Kaggle 匿名数据 API 于本次审计返回 HTTP 401，故本版本不依赖 CAFA5；CAFA4 官网两个数据链接当时返回 404。它们不影响上述 CAFA3 已下载证据。
- **GRIMM EC_v2 五划分与 pseudo-OOD 是另一任务、另一标签体系和另一划分，不能替代 CAFA3 时间留出。** 本卡完成不等于已经取得 CAFA 模型性能或 SOTA。
