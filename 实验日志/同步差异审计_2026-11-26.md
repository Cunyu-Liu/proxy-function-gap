## 2. 去重规则与差异

1. 可解析 JSON 按 canonical JSON 的 SHA256 去重，保留第一次出现的原始字节；不是按 `run_id` 单键覆盖。
2. 损坏行不能 canonicalize，按原始行 SHA256 去重并原样保留，不尝试修复或拆成两条记录。
3. 本地原 364 行是同步后文件的字节相同前缀；远端 306 条唯一记录按远端顺序追加，80 条重叠记录不重复写入。
4. 派生 run/attempt 键为 `run_id + config.out/outputs + seed + start_utc`。因此同秒、同 `run_id` 但不同输出目录或 seed 的 run 不合并，同目录的恢复尝试也不互相覆盖。
5. start/finish 以 `run_id + config.out + seed + start_utc` 精确配对。派生有效状态优先级为 `invalidated > completed > failed > running`；原始状态序列全部保留，终态冲突单独标记，`running` 永不覆盖终态。
