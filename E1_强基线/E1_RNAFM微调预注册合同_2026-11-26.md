# E1 RNA-FM LoRA/full 强基线预注册小合同

日期：2026-11-26 ｜ 状态：pilot 前冻结 ｜ 数据版本：`e0-v2-id90-strict3train-main`

## 范围与证据边界

本合同只补齐 RNA-FM LoRA 与全参微调强基线，不启动 M1b–M1f，不改写已验收 frozen BCE/kNN 或 E5 结果。旧 fold0/seed0、3 epoch 微调只作历史。完整五折三 seed 双轨矩阵及三遍验收全部通过前，不写 SOTA、完整最强基线胜利或机制因果结论。

## 数据与划分

- 主集为 `main_exps.txt` 的 146 实验；每 fold、每 seed 均跑 neg1c/neg2 双轨。
- test=fold `f`，validation=fold `(f+1)%5`，train 显式白名单为其余三个 fold；正负例均排除 fold=-1。
- pilot 只用 fold0/seed0 和指定小实验清单，做 CUDA 数值、反向、有限 loss/validation、早停与 checkpoint 恢复检查，不产生 test 指标，不进入正式性能矩阵。
- 每个任务保存 train/val/test 折计数与 train ID 哈希；正式评价只读取对应 best checkpoint。

## rank 选择与 test 隔离

1. 仅在 fold0/seed0 主集分别训练 r=4、8、16 的 validation-only run。
2. 对每个任务按 validation AUPRC 早停；以接受最佳点的 validation AUPRC 为任务分数。
3. 在 tail RBP 上对实验×双轨任务等权宏平均，选择均值最高的**单一全局 rank**；并列时取较小 rank。选择结果写入带输入哈希的 `selection.json`。
4. rank 冻结后，fold0 三 seed 与其余四折三 seed 不再搜索 rank。full 使用上表固定对照，不参与 rank 选择。
5. `train` 命令不读取 test 序列、不写 test 指标。`evaluate` 仅在配置冻结后加载 best checkpoint，独立写最终 test 结果；任何 test 数字都不反馈给配置、epoch、rank、fold 或 seed 选择。

## 收敛、产物与门控

- 每任务最多 1000 epoch，patience=20，min_delta=1e-4；仅当 `stopped_epoch=best_epoch+20` 且 `stopped_epoch<1000` 才通过收敛门。触及 1000 为故障保险失败。
- 每 epoch 写 train loss、validation AUROC/AUPRC、是否接受新最佳；每任务保存 best checkpoint、validation 预测、split audit、配置、run JSONL 和日志。checkpoint 含模型/分类头状态、任务、seed、折、配方与 CUDA 证据。
- fold0 必须先完成三 seed × LoRA/full × 双轨的训练、独立 test 评价和机器门控，才能启动 fold1–4；五折全部完成后另行三遍验收。
- LoRA/full 可用 nohup 双 worker 并行，每 worker 同时至多一个训练进程。启动前及每个 run 边界检查 CUDA 数值/反向探针、GPU 空闲显存、主机可用内存和 `/teams` checkpoint 容量；不足则等待或明确阻塞，禁止 OOM 后 CPU 降级。
- 大产物仅写 `/teams/HoulabData_1788502323/liucunyu/ProxyFunctionGap/RARESeq/e1_rnafm_finetune_strict3train_p20/`；代码、驱动状态与日志写 `/home/ProxyFunctionGap/`。
- checkpoint 存储补充（首个成功 checkpoint 前冻结）：每任务只保存最佳 FP32 encoder/head 权重，不保存 optimizer 或旧 epoch 权重。`torch.save` 后以 zlib-1 单分片压缩，manifest 记录原始/压缩 SHA256、字节数与格式；保存后执行解压 SHA roundtrip、`torch.load` 和逐 tensor bitwise 对比，通过才标记任务完成。评价恢复产生的本任务临时文件必须在 `finally` 中清理。容量预检按 0.70 压缩比并预留 20GiB；不足时阻塞，绝不通过省略 checkpoint、降精度、删既有数据或缩减矩阵过门。

## Artifact retention（产物保留，不改变科学协议）

科学验收要求每任务最佳 checkpoint 曾经完整保存、通过双 SHA/bitwise 恢复、在 CUDA 上重载复现 validation 并用于 test；不要求永久保存每个 baseline 的全参 encoder。以下策略只改变训练完成后的产物保留周期，不改变模型、数据、rank/epoch 选择、test 指标或矩阵：

1. 每任务依次完成 best FP32 压缩权重→双 SHA/bitwise 重载→validation 复验→独立 test 预测。配置、history、validation/test 预测及其 SHA、checkpoint 压缩/恢复证明和小分类头永久保留；均值掩码池化无 scaler，记录 `scaler=none`。
2. 逐 run 独立验收通过后，非代表性任务仅保留上述小产物与证明，可清理本任务新生成的压缩 encoder/adapter。清理前必须核对 run/task 实名路径位于本阶段 `/teams` 新产物根目录、文件名严格为 `best.pt.zlib`、不是符号链接、SHA 与 manifest 一致且 train/eval/独立验收均完成。先写 retention plan，删除后再写最终 retention 状态；禁止通配符或跨任务删除。
3. 永久保留 pilot 两种模式的完整 checkpoint。正式矩阵中，对 fold0/seed0 的 validation 晋级 LoRA rank 与 full 对照，按 head/mid/tail 各取实验名字典序首个实验并保留双轨完整 checkpoint；该代表集只由 fold/seed/tier/实验名决定，绝不读取 test 选择。
4. 非代表性完整 checkpoint 的清理发生在独立验收之后；后续验收必须接受带完整证明的 `retained_proof_only`，代表性任务则继续要求原压缩权重存在。任何证明、head、预测或哈希缺失都禁止清理。
5. 峰值容量按“一个活动 run 的完整 checkpoint + 永久代表集 + 全矩阵小 head/预测/history + 20GiB 预留”预算。空间不足仍等待，不删除既有数据或缩减矩阵。

## 三遍验收

1. 文件/schema/有限值：run、配置、history、split audit、best checkpoint、validation/test 预测和日志齐全。
2. 合同重放：严格三折与 fold=-1 排除、seed/fold/track/rank 对齐、CUDA 探针、早停点与 checkpoint 恢复一致；rank 搜索目录无 test 产物。
3. 独立回算：由逐任务预测重算结果和汇总，逐值匹配；确认所有配置选择只引用 validation，且矩阵完整前不形成 SOTA 表述。
