## strict3train 训练与评价

- test fold 为 `f`，validation fold 为 `(f+1)%5`，train 仅使用其余三个 fold；`fold=-1` 不得进入 train。
- BCE：5 folds × seeds 0/1/2，共15个独立 run；每 run 为146实验×2轨=292个任务。
- BCE 每任务按 validation AUPRC 早停并恢复最佳 checkpoint；`patience=20`、`min_delta=1e-4`、`epochs=1000` 故障保险。test 只在恢复最佳 checkpoint 后评价。
- kNN：5 folds，共5个独立 run；训练正样本按冻结 id90 cluster 去重，负样本不变。k∈{5,10,20}，按 tail-RBP 平均 validation AUPRC 分轨选 k，随后才输出 test。
- RiNALMo kNN 使用逐任务加载、只保留分数与 IDs 的低内存实现，避免1280维全矩阵多份驻留导致主机 OOM。
- 每个正式 BCE run 必须保留 run JSONL、validation history、292个最佳 checkpoint、split audit、val/test predictions 和日志；kNN 必须保留 run JSONL、全部 k 的 validation history、split audit、val/test predictions 和日志。

## 资源门控与队列

- 驱动以 `nohup` 和独占 `flock` 运行；嵌入/训练前检查 GPU 可用显存和 `/proc/meminfo` 的 MemAvailable，不满足时每300秒重查，不做频繁显存监控。
- 2026-11-27 配额失败后增加存储门控：嵌入至少3 GiB、每个 BCE/kNN run 至少1 GiB可用空间，不满足时每300秒等待；失败日志与临时文件保留，不删除缓存。
- BCE GPU 门控可用 `BCE_GPU_FREE_MIB` 校准，`BCE_WORKERS` 可设为1或2；只改变调度，不改变科学 batch/模型。最大 fold0 任务实测外部峰值870 MiB，1,920 MiB门控含1,050 MiB余量；本轮两个既有 worker 已在原6,000 MiB门控下启动，因此不强制重启或追加第三个 worker。
- smoke 后先完成正式 fold0/seed0 BCE 与 fold0 kNN 并审计，再以两个 BCE worker 跑剩余14个 run；kNN 单 worker，避免 RAM/GPU 峰值叠加。
- 任一任务失败则驱动状态写为 `FAILED`，不得以部分矩阵生成正式完成结论。
