# E0 设计：固定完整序列候选池合成验证

## 范围与备选方案

仅实现 E0：有限、固定、完整序列候选池上的 top-1 选择与合成正确性验证。不使用真实标签，不训练模型，不调用 GPU，不生成前缀或新序列。

曾考虑三种实现路线：

1. **惰性计分函数 + 统一预算计数器（采用）**：候选池只含 ID、序列、基础提议概率和可行性；proxy/V 通过函数注入。重复候选默认不缓存，调用数与算法实际计分次数一致。
2. 一次性向量化所有分数：实现较短，但所有候选预先计分会使 BoN、拒绝采样和重复提议的调用预算失真，弃用。
3. 直接移植生成式 VGSC：超出固定池 E0 范围，且引入前缀真值不可校准问题，弃用。

## 组件与数据流

- `pool.py`：校验有限候选池；在提议前应用硬约束掩码并重新归一化；计算解析倾斜分布。
- `constraints.py`：UTR 长度、GC、uAUG、poly-U 掩码。全长 CDS 阅读框约束不在 E0。
- `selection.py`：random、BoN、WSC、greedy、V-only 和 joint；惰性计分、分模型计数、预算上限、可复现 RNG。
- `synthetic.py`：已知 `proxy = truth + structured_bias + Gaussian_noise` 的纯合成案例。
- `metrics.py`：仅在合成评分侧使用真值计算 regret；可行候选中的 oracle 为参照。
- `run.py`：冻结配置的端到端 smoke runner，输出确定性的 JSON 和配置哈希。
- `tests/` 与 `checks/`：接口/数学性质、预算公平、独立参考实现检查。

## 错误处理

非法概率、重复 ID、非有限分数、越界 V/Q、负 alpha、非正预算、无可行候选和预算超限均显式报错。全部拒绝且回退权重和为零时，在已缓存提议中均匀选择；该退化规则写入协议，不静默改用 proxy 或真值。平分候选保留最早提议者。

只有完整 pytest、独立数学检查、预算公平检查、代码审查和同种子重复运行全部通过才判定 E0 通过。日志、JSON、环境版本和审查结论保存到 `/teams/HoulabData_1788502323/liucunyu/proxy_function_gap/e0/`。E0 只证明实现符合冻结定义，不证明任何策略在生物任务上有效。
