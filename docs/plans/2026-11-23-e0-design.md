# E0 设计：VGSC-inspired fixed-pool 合成验证

## 范围

仅实现固定完整序列候选池上的选择与合成正确性验证。FP-REJ 是主方法，FP-TILT 是解析对照；不实现前缀生成、真实标签、训练或 GPU 路径。

## 设计取舍

1. **单轨迹原语 + 共享预算多轨迹（采用）**：FP-REJ 单轨迹只输出 top-1/拒选；多轨迹身份投票产生不放回 top-k。比在单次拒绝采样中强行返回 top-k 更接近多轨迹语义。
2. **统一 item-forward 计分层（采用）**：普通 scorer、BatchScorer 和 ensemble 都经过同一计数器；cache 只有显式实例才启用。
3. **FP-TILT 只含 V（采用）**：池级 Q 不进入精确选择，避免把归一化约去或有限接受率差异误写成精确增量。
4. 一次性预评分全库：仅 FP-TILT 因解析定义需要；其他策略保持按需/按批计分，否则预算失真。
5. 直接移植生成式 VGSC：超出 E0，不采用。

## 组件

- `pool.py`：候选池、掩码和 FP-TILT 解析分布。
- `budget.py`：实际 item-forward、batch、ensemble、cache、Q 和聚合权重。
- `selection.py`：Random/BoN/WSC/greedy/FP-TILT/FP-REJ，单轨迹与多轨迹结果。
- `noise.py`：V/Q 概率 logit 噪声。
- `synthetic.py`：adversarial、independent、oracle 合成场景。
- `metrics.py`：选择后的合成 regret。
- `run.py`：冻结配置、确定性 JSON 和配置哈希。

## 错误与退化

默认全零显式拒选；只有显式 uniform 配置才回退。非法概率、非有限分数、负 alpha、非正预算、batch 长度不符、无可行候选和预算超限均报错。平分按首次出现或池顺序，top-k 不出现重复身份。

## 验收

完整 pytest、C=1/2/3 独立全路径检查、源码审计和同配置双运行全部通过才提交。E0 通过不证明生物策略有效，不触发 E1。
